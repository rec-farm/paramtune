<task type="auto">
  <name>Task 3: Protect server action JSON.parse</name>
  <files>src/app/dashboard/[platform]/[version]/page.tsx</files>
  <action>
Wrap the JSON.parse in updateSchema server action (line 33) with try/catch:

```typescript
async function updateSchema(formData: FormData) {
  'use server'

  let content: unknown
  try {
    content = JSON.parse(formData.get('content') as string)
  } catch {
    throw new Error('Invalid JSON content')
  }

  await saveSchema(platformName, versionName, content)
  revalidatePath('/dashboard/[platform]/[version]', 'page')
}
```

This provides a meaningful error message instead of generic parse failure. The error will be caught by the error.tsx boundary and displayed to the user.

Note: The SchemaEditorForm already validates JSON before submission (Phase 2), but this is defense-in-depth for direct form submissions or edge cases.
