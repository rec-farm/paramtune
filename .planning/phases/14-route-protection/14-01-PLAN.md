2. Update the `config.matcher` to include dashboard routes: `['/api/:path*', '/dashboard/:path*']`
3. Add dashboard protection logic BEFORE the CORS logic:
   - Check if path starts with '/dashboard'
   - If so, check for session cookie using `getSessionCookie(request)`
   - If no session cookie, redirect to `/login?returnTo={encodedPath}`
   - Use `encodeURIComponent(request.nextUrl.pathname + request.nextUrl.search)` for returnTo
   - Return `NextResponse.redirect(new URL(\`/login?returnTo=\${returnTo}\`, request.url))`
   - If has session cookie, continue to CORS logic

4. Keep all existing CORS and security header logic intact for API routes

Pattern from research:
```typescript
import { getSessionCookie } from "better-auth/cookies"

// In middleware function, before CORS logic:
if (request.nextUrl.pathname.startsWith('/dashboard')) {
  const sessionCookie = getSessionCookie(request)
  if (!sessionCookie) {
    const returnTo = encodeURIComponent(request.nextUrl.pathname + request.nextUrl.search)
    return NextResponse.redirect(new URL(`/login?returnTo=${returnTo}`, request.url))
  }
}
```

Important: Middleware cookie check is UX optimization only. Server Component validation in Task 2 is the actual security layer.
